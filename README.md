# Rabb.ai

A free Christian Bible habit app with a premium AI Bible learning platform. Before the scroll, seek the Word.

Users pick apps to restrict. Those apps stay restricted until the user reads the day's verse and prays (plus an optional reading timer). Premium adds an AI Bible tutor, learning paths, quizzes and advanced progress.

Project rules live in `AGENTS.md`. Current state lives in `docs/STATUS.md`. Start with `docs/IMPLEMENTATION_PLAN.md`.

## Repository layout

```
apps/mobile            React Native (bare, New Architecture, Hermes) with committed ios/ and android/
  modules/rabb-blocking  Swift and Kotlin Expo module (Screen Time, Android detection) plus iOS extension sources
apps/admin             README only
packages/contracts     Zod schemas shared by app and Edge Functions
packages/ritual-engine pure ritual state machine
packages/schedule-core day boundary, recurrence, DST, restriction resolution, streaks
supabase/              migrations, functions (Deno), tests (pgTAP), seed, ai-evals
docs/                  plans, architecture, risk register, security, privacy, platform guides
scripts/               database runners, test runners, generators
```

## Initialize

```bash
corepack enable
pnpm install
cp .env.example .env
cp apps/mobile/.env.example apps/mobile/.env
```

Fill in public client values in `apps/mobile/.env`. Server secrets go to Supabase secrets, never into the app.

## Verify everything

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm db:reset
pnpm db:test
pnpm functions:test
pnpm ai:evals
pnpm --filter @rabb/mobile android:logic-test
pnpm docs:api
```

`db:reset` and `db:test` use `supabase db reset` and `supabase test db` when the CLI and Docker are present. Otherwise they use `scripts/db-local.sh` on a local PostgreSQL 16 (pgvector and pgTAP installed, for example `apt install postgresql-16-pgvector postgresql-16-pgtap pgtap`). `functions:test` needs the same database. It uses `postgresql://postgres:postgres@127.0.0.1:5432/rabb_local` unless `RABB_TEST_DB_URL` is set.

## Backend

```bash
supabase start
supabase db reset                       # migrations plus DEV ONLY seed fixtures
supabase functions serve --env-file .env --no-verify-jwt=false
# deploy
supabase link --project-ref <ref>
supabase db push
supabase secrets set --env-file .env    # server values only
supabase functions deploy v1
supabase functions deploy revenuecat-webhook --no-verify-jwt
```

The API is the function `v1`: `https://<ref>.supabase.co/functions/v1/v1/<path>`, for example `/v1/daily/ritual`. Endpoint reference: `docs/API_SPECIFICATION.md` (generated by `pnpm docs:api`). Set the RevenueCat webhook URL to the `revenuecat-webhook` function with the Authorization header value from `REVENUECAT_WEBHOOK_SECRET`.

Edge Functions import the workspace packages by relative path through `supabase/functions/deno.json`. Confirm the first deploy bundles them (unverified in this repository, see `docs/RISK_REGISTER.md`).

## Android

```bash
pnpm --filter @rabb/mobile assets:link          # link Inter and Newsreader fonts
cd apps/mobile
pnpm start                                      # Metro, in one terminal
pnpm android                                    # build and run on a device or emulator
```

Android needs the Expo Modules autolinking edits already applied in `android/settings.gradle` (see `docs/ANDROID_BLOCKING.md`). Blocking needs a real device with Usage Access and overlay permissions. Capability tiers and OEM guidance are in `docs/ANDROID_BLOCKING.md`.

## iOS

```bash
cd apps/mobile/ios && pod install && cd ..
pnpm start
pnpm ios --device                               # physical device only for Screen Time
```

Family Controls needs a development entitlement and works on physical devices only. Add the three extension targets in Xcode and wire the sources under `modules/rabb-blocking/ios`. Exact steps, bundle IDs and the Apple entitlement request text are in `docs/IOS_SCREEN_TIME.md`. Never run `expo prebuild`.

## Status and honesty

Native blocking is written but not yet verified on a device. `docs/STATUS.md` lists every capability as IMPLEMENTED, MOCKED, BLOCKED or NOT_STARTED, with blockers. Rabb.ai never claims a restriction is applied unless the native layer reports it, and never claims guaranteed enforcement on Android.
