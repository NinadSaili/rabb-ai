# Risk register

Likelihood and impact: L (low), M (medium), H (high). Owner is a role, not a person. Status values: open, mitigating, accepted, closed.

| ID | Risk | Likelihood | Impact | Owner | Mitigation | Status |
|----|------|-----------|--------|-------|-----------|--------|
| R1 | Apple Family Controls distribution entitlement is not approved, or approval takes weeks. Needed for the app and each of the three extension bundle IDs. | H | H | Product owner | Request the entitlement for all four bundle IDs in week 1 (text in `IOS_SCREEN_TIME.md`). Development entitlement works on devices meanwhile. App detects missing entitlement and falls back to Tier 0 reminders with honest copy. Ship Android first as already planned. | open |
| R2 | Google Play policy on overlays (SYSTEM_ALERT_WINDOW), foreground services and AccessibilityService leads to rejection or removal. | H | H | Android lead | Overlay path stays behind feature flags with prominent disclosure and consent. AccessibilityService is a separate flavor, flag default off, not shipped without owner approval. No QUERY_ALL_PACKAGES. Policy analysis in `ANDROID_BLOCKING.md`. Pre-launch review with Play policy support contact. | open |
| R3 | OEM background killing (Xiaomi, Samsung, Huawei, Oppo, Vivo) stops the foreground service so apps are not blocked. | H | H | Android lead | Capability tiers and status screen state what is enforced. Battery optimization exemption guidance per OEM (link and steps). Watchdog via WorkManager and boot receiver. No claim of guaranteed enforcement anywhere in UI or store copy. | open |
| R4 | Bible licensing: using a translation without verified commercial and AI usage rights. | M | H | Content owner | Default to Berean Standard Bible, World English Bible and KJV only. Verify each from the primary source and record in `SCRIPTURE_LICENSING.md` before inclusion. Fixtures labelled DEV ONLY and excluded from release builds. Release gate checks every shipped translation has a verified row. | open |
| R5 | AI cost overrun and abuse (scripted calls, prompt stuffing, premium account sharing). | M | H | Backend lead | Per user daily and monthly token budgets in `ai_usage_ledger`, per user rate limits, input length cap, global kill switch in `feature_flags`, streaming with server cutoff, model names from env. Alerts on global daily spend. | open |
| R6 | App Store or Play review rejection (restriction claims, subscription disclosures, account deletion, data safety mismatch). | M | H | Product owner | Release checklist maps each guideline to evidence. In app account deletion. Paywall shows price, period, trial terms, renewal and cancellation text, restore, terms and privacy. Store copy describes restriction honestly. Reviewer notes explain Family Controls use and give a demo path. | open |
| R7 | Spikes cannot run in the authoring environment (no Xcode, Android SDK or devices). Native code is written but unverified on device. | H | H | Engineering lead | Everything native is labelled BLOCKED with the exact device protocol. Pure logic is extracted to TypeScript and pure Kotlin and tested off device. First device session is a gating task before any beta. | open |
| R8 | Shield extensions cannot launch the host app. A user who sees a shield may not find a path back to the ritual. | H | M | iOS lead | Shield copy points to a local notification (Notifee scheduled by the ShieldAction extension via a UNUserNotificationCenter request). Verify the extension can post notifications on device. Fallback copy tells the user to open Rabb.ai from the home screen. | open |
| R9 | Offline timer completion cannot be validated against server received timestamps. | M | M | Backend lead | Server marks offline-reconciled timer steps `timer_verified = false`. They still complete the ritual (unlock is local) and count for streak. Documented trade-off; revisit if streak fraud appears. Online path enforces 5 percent tolerance. | accepted |
| R10 | Node 22 is installed here while the project locks Node 20 LTS. | L | L | Engineering lead | `.nvmrc` and `engines` pin 20. CI uses Node 20. Local checks run on 22 and are re-run on 20 in CI. | open |
| R11 | Supabase CLI and Docker daemon are unavailable here, so `supabase db reset` and `supabase test db` cannot run. | H | M | Backend lead | Migrations are plain SQL in `supabase/migrations`. `scripts/db-local.sh` applies them to a local Postgres 16 with pgvector and pgTAP and runs `pg_prove`. CI runs the real Supabase CLI. Auth schema stubs live in `supabase/tests/support` and are used only by the local runner. | mitigating |
| R12 | Prayer journal content leaks into logs, analytics, Sentry or AI prompts. | L | H | Privacy lead | Allow listed analytics, Sentry scrubbing tests, journal excluded from tutor retrieval unless `ai_opt_in` is true for that entry, lint rule banning journal fields in logger calls, pgTAP for opt-in. | open |
| R13 | iOS application tokens are opaque so the UI cannot list selected app names. | H | L | iOS lead | Render with SwiftUI `Label(token)` through a native view. JS receives counts only. | accepted |
| R14 | Streak integrity: clock manipulation, timezone hopping. | M | M | Backend lead | Server computes `local_date`, session bound to start date, unique completion per schedule and date, idempotency keys. | mitigating |
| R15 | Brand font licensing for scripture font. | L | L | Design lead | Newsreader and Inter are OFL. Bundle license files in the app. | open |
| R16 | Offline start binds to the server receipt date. A ritual started offline before 03:00 and synced after 03:00 counts for the later ritual date. | L | L | Backend lead | The OS unlock is local and unaffected. Streak impact is one day at most. Accepted for v1. A client supplied start time would let a device clock influence streaks. | accepted |
| R17 | "Unlock until midnight" on a window that crosses midnight left the user restricted with no way to unlock again. | L | M | Product owner | Resolved by design: the database, API and form now reject midnight unlock for windows that cross midnight, and the option is not offered in the UI. Wording of the option is still an owner decision. | mitigating |
| R18 | Expo Modules autolinking edits (Podfile, settings.gradle) and the local module layout were written from documentation and not built (no Xcode, no Android SDK). | H | M | Engineering lead | First Mac and Android Studio session builds both. If SDK drift breaks them, run `npx install-expo-modules` once and re-apply the module. | open |
| R19 | DeviceActivity needs intervals of at least 15 minutes and caps schedules, so very short windows and far-future windows cannot be registered. | M | M | iOS lead | The app registers the next 16 windows of 15 minutes or more and re-registers on each launch and foreground. Verify limits in spike S7 and S12. UI says when a window is too short to enforce. | open |
| R20 | ShieldAction may not be able to post a local notification, so the secondary shield button may do nothing visible. | M | M | iOS lead | Shield copy already says to open Rabb.ai from the home screen. Verify in spike S10 and change the copy if needed. | open |
| R21 | Apple and Google account linking for an anonymous user uses `linkIdentity` through the system browser. Native ID token flows sign in as an existing account and do not link. | M | M | Auth lead | Email linking keeps the same user id. For OAuth providers the app uses `linkIdentity`. Needs provider configuration and live testing. | open |
| R22 | The AI tutor runs on a MOCK provider in tests and by default (`AI_PROVIDER=mock`). The OpenAI provider is code complete but never exercised against the live API here. | H | M | Backend lead | Run `pnpm ai:evals` with `AI_PROVIDER=openai` and real keys before any beta. The pipeline verifies every quotation regardless of provider. Pass criteria are in `supabase/tests/ai-evals`. | open |
| R23 | Android `targetSdk` follows the React Native template (36) and may lag the current Play requirement. | M | M | Android lead | Check the Play requirement before each release and bump `android/build.gradle`. | open |
| R24 | The workspace uses `node-linker=hoisted` for React Native tooling compatibility. | L | L | Engineering lead | Revisit if pnpm isolated mode becomes supported by the RN toolchain in use. | accepted |
| R25 | Streaming sends verified blocks, not tokens, so the first byte arrives after verification completes. | M | L | Backend lead | Accepted. Streaming raw tokens would expose unverified quotations. | accepted |
| R26 | Tutor retrieval has no editorial corpus yet. `content_chunks` is empty until `pnpm ai:ingest` runs against approved, license-verified content (DEV ONLY fixtures need `INGEST_ALLOW_DEV=1`). | H | M | Content owner | Verify translation licences, approve a first corpus, run the ingestion script. Until then the tutor answers that it found nothing relevant. | open |
| R27 | Android APK cannot be built in the authoring environment (no SDK, NDK or `adb`; `dl.google.com` blocked). The APK is built by the `android-apk` GitHub Actions workflow instead, and compile errors are fixed by reading CI logs. | H | H | Engineering lead | Workflow `.github/workflows/android.yml` builds a debug-signed APK as an artifact. Status in `docs/STATUS.md` records exactly what CI has and has not built. A real device install is still required before any claim of a working app. | open |
| R28 | Demo mode ships placeholder KJV text labelled DEV ONLY. KJV is public domain in the United States, but the Crown holds letters patent in the United Kingdom, and the licence is unverified from the primary source. | M | M | Content owner | Demo APK is for a private demonstration only and carries a banner. The release gate (database constraint, RLS flag, release bundle check) prevents it from entering a release. Owner decides whether to demo with another verified public domain text. | open |
| R29 | Demo mode simulates restrictions. Presenters may overstate it as real enforcement. | M | H | Product owner | Banner on every screen, "Restricted (simulated)" and "Unlocked (simulated)" labels, demo script in `docs/DEMO_GUIDE.md` says not to claim real blocking. | open |
| R30 | An unverified (offline) timer step still lets the ritual complete server side and count toward the streak. Local unlock never depends on the server, so it is unaffected. | M | L | Backend lead | Completion response reports `timer_verified`. Accepted trade-off for offline users (R9). Revisit if streak fraud appears. | accepted |
| R31 | The APK manifest includes permissions pulled in by libraries that Rabb.ai does not need to declare: USE_BIOMETRIC and USE_FINGERPRINT (react-native-keychain) and READ and WRITE_EXTERNAL_STORAGE up to API 32. They would appear in Play permission and Data safety review. | M | L | Android lead | Remove with `tools:node="remove"` in the app manifest after confirming nothing needs them, then re-run the APK inspection step. | open |
| R32 | The release APK is signed with the public debug keystore. Anyone can rebuild an APK that updates over it. | H | L | Engineering lead | Acceptable for a private demonstration only. A store build needs its own keystore and Play App Signing. | accepted |
